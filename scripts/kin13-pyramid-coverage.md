# Kin 1.3 current test-pyramid coverage map

Head: `045f58bc0393c8c720b0557fb0fd90a9aeb7b8d2` ([PR #58](https://github.com/dannydover/Kin/pull/58)). This is an inventory and coverage decision map, not evidence that the suite is reliable. No UI journey is retired by this document.

The 69 current `test*` methods are enumerated from all nine test-bearing UI files at this head. Sixty-two descriptions inherit the prior manual review at `bce9eb3`; seven new or split methods are mapped below. Current test bodies were compared with that baseline for changed assertions; helper and fixture revisions mean the inherited descriptions are a review aid, not a fresh proof of every assertion or exact runtime equivalence. References to previous run statuses in inherited descriptions are historical. The current required workflow and first-attempt failure evidence remain authoritative.

## Representative journeys and lower-layer boundaries

- Keep real native Contacts selection, review, cancellation, adult/minor birthday and photo paths, including owned-contact cleanup; keep a real Photos selection and persistence path. Pure import and photo policy tests do not establish native presentation or system payload behavior.
- Keep critical real app UI for create/save/relaunch, Friend toggle persistence, relationship create/reject/cancel, deletion confirmation, search/filter recovery, and accessibility at standard and largest text. The model tests cover combinatorial business rules, not UI wiring or geometry.
- `ExistingPersonChoicesTests`, `PeopleFilterStateTests`, `FilterStoreSequenceTests`, `SequentialImportRestartTests`, graph/store tests, age and photo policy tests cover deterministic rules. The added chooser test in this directory checks search-empty-clear duplicate identities and leaves all UI tests intact.
- The three pure harness decisions in `NativeContactsTests` are the clearest lower-layer migration candidates. First extract test-only shared primitives without changing the native helpers, add equivalent lower-level tests and prove CI/release exclusion and cleanup-gate parity. Running those decisions under a different OS/runtime loses their execution on iOS unless a representative integration check remains; document and validate this before any retirement.
- The combined-filter original and preview repeat the same observable Clear sequence but use persisted/UI-created versus preview fixtures. Prior test-only fixture and store tests reduce the business-rule gap; deleting either UI method would still remove its distinct setup-to-control integration and must be explicitly reviewed. The compound deletion journey versus split candidates similarly loses same-notebook continuity if removed.
- The two missing-birthday photo paths share review and saved-state assertions; one exercises real Photos setup and one uses a synthetic saved-photo fixture. Keep the real journey and disclose any proposed removal of the independent fixture path. Four reviewed-import routes preserve a sequential relaunch journey beyond their lower-level store test.
- Candidate reductions are opportunities, not approvals. Preserve required checks, failures, no-skip accounting, and original native and continuous journeys until replacements and any coverage tradeoff are reviewed.

## Additive local migration candidate

The isolated `extraction/` candidate moves the existing pure `syntheticCardResolution`,
`preciseFormFrameIsVisible`, reveal deadline and reveal policy source from the UI
helper into the already-shared `KinTests/Shared/SyntheticContactsCleanup.swift`. This
keeps the guarded Xcode project configuration unchanged, at the cost of placing
two test-support responsibilities in the same file. Apart from access modifiers,
imports and an explicit initializer, the extracted policy body matches the
original. The UI target already includes that same source; the three existing UI-target
policy tests remain unchanged. Three new lower-level test functions reproduce
all 23 existing assertions. The separate chooser model test covers the
empty-search/reset duplicate-identity sequence without replacing its UI journey.

Local macOS Swift package validation passed 103 tests across 22 suites. The full
current UI-source copy plus the extracted support type-checked against the local
iOS simulator SDK. An unsigned Release app from a local checkout copy passed the
existing Release guard and contained no policy markers. These are local Xcode 27.2
checks, not hosted Xcode 27.0 or iOS simulator execution. Current app and core
files were verified against head where used in the package test; the local Release
app was not built from an exact remote checkout. All three UI-target policy tests
and all native journeys remain required. The prior hosted run 41741180017 failed three tests. The first extraction attempt
(run 41748618781) failed the repository identity guard because it added an Xcode
UI source reference; the revised local candidate preserves the original project
file and the guard, and all four local identity tests pass. This extraction is not
a demonstrated fix for the earlier UI failures.

Hosted run [41748618781](https://github.com/dannydover/Kin/actions/runs/41748618781)
finished with 224 passed, three failed and zero skipped across finalized test
bundles. The failures were an automatic-gender assertion in adult Contacts review,
a membership-journey timeout, and failure to reveal the Friend switch. The
repository identity check also failed on the added UI source reference. These
failures remain unresolved; the shared-file correction addresses only the
identity check and does not establish a fix for UI reliability. Simulator
cleanup records and the owned synthetic Contacts cleanup markers were verified.
