# Fixed-product Xcode comparison

This one-time, nonshipping diagnostic compares XCTest execution under Xcode 27.0 and 27.1. It does not modify the required CI workflow, change the release toolchain, approve a release, or convert a failed test into a passing result.

The workflow starts only for PR 58 when the synchronized head commit has the exact one-time marker in its subject. It waits for ordinary PR CI on that head to finish, retaining its original conclusion. The experiment checks out source `022e405fe6d301df9b2e4c936f91f32065ba996d`, verifies a clean tree, and builds unsigned test products once under Xcode 27.0. The archive and the complete extracted-product hash, mode, and link manifest must match before every preflight and arm. Products contain only the public source's synthetic test app and test bundles; they are retained for seven days.

Two separate fresh-simulator preflights run one existing synthetic app UI test using the identical products and `test-without-building`, first under 27.0, then 27.1. An unsuccessful preflight is not classified as a toolchain defect: it stops the comparison with its result retained. Every job requires the same GitHub runner image version and iOS 27.0 runtime build `24A434`; an unavailable or mismatching control stops the comparison. Xcode 27.1 compatibility with these products and runtime is checked, not assumed.

The four sequential arms run 27.0, 27.1, 27.0, 27.1. Each arm uses the same four UI shards and full unit/integration target, on five separately provisioned hosted simulators. Each uses the original test selection, execution limits, synthetic Contacts and Photos setup, and test cleanup accounting. Finalized result identities, zero skips, result evidence, owned Contacts cleanup, simulator cleanup, product hashes, image and runtime must verify before the next arm. A complete failed test remains a failed job and is retained; the gate verifies comparability, not success. An incomplete result, missing cleanup, product mismatch or infrastructure failure stops later arms rather than being retried.

Result bundles, fixed-field progress, setup timing and cleanup are retained for seven days. The fixed-source observer records first observed failure and per-test progress; GitHub job timestamps record queue and completion. Compare failed versus passed tests and execution durations as observations. Two samples per arm are not a failure-rate estimate and cannot prove either toolchain reliable. Shared build products isolate toolchain execution better than separate builds, but build-once execution differs from the normal build-and-test workflow, and matching image versions cannot eliminate hosted-machine variation.
